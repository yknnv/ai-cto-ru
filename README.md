# Внедрение ИИ в разработку: курс для CTO и лидов

[![Лицензия: CC BY-NC 4.0](https://img.shields.io/badge/лицензия-CC%20BY--NC%204.0-lightgrey.svg)](LICENSE.md)
[![Онлайн-версия](https://img.shields.io/badge/онлайн-ykononov.ru%2Fai--cto-2457c5.svg)](https://ykononov.ru/ai-cto/)
[![Телеграм-бот](https://img.shields.io/badge/бот-@ai__cto__course__bot-26A5E4.svg)](https://t.me/ai_cto_course_bot)
[![Telegram](https://img.shields.io/badge/Telegram-@ykononovmd-26A5E4.svg)](https://t.me/ykononovmd)

Бесплатный курс о том, как перевести разработку на работу с ИИ-ассистентами и ИИ-агентами (Claude Code, Cursor, GigaCode, GitHub Copilot) и не потерять контроль над деньгами, безопасностью и качеством. Для технических директоров, руководителей разработки и лидов.

15 блоков: экономика токенов и окупаемость, безопасность и требования 152-ФЗ, Банка России и ФСТЭК, метрики DORA, работа с людьми и план пилота на 90 дней. Данные на 2026 год, российская специфика, ссылки на первоисточники.

- в Телеграм-боте: [@ai_cto_course_bot](https://t.me/ai_cto_course_bot);
- в репозитории на GitHub: [github.com/yknnv/ai-cto-ru](https://github.com/yknnv/ai-cto-ru).

Шаблоны и промпты курса отдельным репозиторием-шаблоном для своего проекта: [github.com/yknnv/ai-cto-starter](https://github.com/yknnv/ai-cto-starter).

## Что внутри каждого блока

- ситуация и развилка из 3 вариантов решения;
- исходы каждого варианта через квартал – с последствиями в метриках;
- разбор с цифрами и ссылками на исследования;
- мнения 2 технических директоров: Даниил (банк, первый год внедрения) и Мария (продуктовая компания, второй год);
- промпт: модель задаст вопросы и соберёт рабочий документ под вашу компанию;
- итог блока.

| 03 | [Подходы и практики](blocks/03-ii-agenty-i-podhody.md) | 5 ступеней автономии от автодополнения до агентов, разработка от спецификации, локальная LLM или модель по API |
| 04 | [Экономика ИИ-разработки](blocks/04-stoimost-tokenov-okupaemost.md) | Сколько стоят токены на инженера и на фичу, 4 рычага снижения расходов, модель окупаемости |

| 06 | [Сбор требований](blocks/06-spec-driven-development.md) | Спецификации, по которым ИИ-агент делает предсказуемый код: шаблон, пример, Spec Kit, Kiro, OpenSpec |
| 07 | [Разработка](blocks/07-ii-v-programmirovanii.md) | Генерация кода, понимание легаси, ревью как новое узкое место, рефакторинг и миграции |
| 08 | [Тестирование](blocks/08-ii-dlya-testirovaniya.md) | Тесты, которые ловят ошибки, а не просто зелёные: тестовые данные, автотесты, регресс |
| 09 | [CI/CD](blocks/09-ii-v-ci-cd.md) | CI/CD для сгенерированного кода: SAST, DAST, линтеры, инфраструктура как код |
| 10 | [Сопровождение и метрики](blocks/10-soprovozhdenie-monitoring.md) | Инциденты, мониторинг, журналы и трассировка с ИИ, маскирование данных |
| 11 | [Как измерять эффект от внедрения](blocks/11-metriki-dora-baseline.md) | Baseline и метрики DORA: как доказать эффект через квартал |
| 12 | [Сложности внедрения](blocks/12-slozhnosti-vnedreniya-ii.md) | Узкие места после ускорения: ревью, качество, безопасность, сопротивление |
| 13 | [Люди](blocks/13-komanda-roli-obuchenie.md) | Роли, обучение, джуны и оценка инженеров при переходе на разработку с ИИ |
| 14 | [Практика: первые 90 дней](blocks/14-pilot-90-dney.md) | План пилота на 90 дней: подготовка, пилот, решение о раскатке |
| 15 | [Шаблоны и приложения](blocks/15-shablony.md) | Шаблоны: политика использования ИИ, файл контекста, дизайн пилота, чек-лист для ИБ |

**С чего начать.** Если вы только начинаете: 01 → 02 → 11 → 05 → 04 → 03 → 13 → 14. Если пилот уже идёт: 11 и 12, затем 14 и 15. Блоки 06–10 – справочные, по направлениям разработки.
